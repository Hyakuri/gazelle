## 1. 契约

### 目标

- 把用户在 `20260821` 上画的区域配准到每次录制的 E 画面，固定结构的区域自动到位，不确定时提示人。
- 产出 TASK-153 复核所需的全部文件。本任务不写 `reviewed`，正式结果要等用户确认。
- 只用 CPU，不下载，新录制接入后可以直接运行。

### 必须实现

1. **模块与命令**：`tools/workdata/region_registration.py`，用 `python -m tools.workdata.region_registration <子命令>` 运行。子命令：`policy`、`fingerprint`、`register`、`monitor`。参数都是显式选项，不带默认的数据路径。
2. **区域类型**（§3）：`policy` 写 `gazelle_data\workdata\roi_sessions\region_policy.json`。类型表用设计的值，不写进只读的 `roi\`。
3. **取帧与背景图**（§5、§6）：
   - 全部录制走同一路径：从 E 的 1080p 代理 `proxy_overview.mp4` 取帧。这是协调者的选择，设计没有规定。[实测](../evidence/2026-10-30-region-drift-analysis.md)要求 TASK-151 用同一路径重算；原型不是这样，它的旧 7 次读代理，新录制读源视频。选代理的理由：旧 7 次的原型结果就来自代理，时间轴直接对齐 B，也不需要访问源目录。
   - 在代理网格上均匀取 64 步，跳过 `gap` 与 `sync_uncertain` 的步。
   - 每个像素取最密集的四分之一样本，算法与 `bg_v2.py` 相同。
4. **指纹**（§5）：`fingerprint` 写 `roi_sessions\_fingerprints\<参考录制>\`：背景图、屏蔽、锚点、区域类型、出处（区域文件 SHA-256、背景图 SHA-256、参数版本）。屏蔽按该录制的时钟版式确定。指纹可以重建。
5. **逐区域配准**（§6）：
   - 步骤与参数按 §6 的表，参数集中成一个常量，写入每个结果的 `parameters`。之后不看新录制再改。
   - 模型固定为“粗对齐单应 × 区域仿射”，不做模型选择。`regreg3.py` 里的 `R3_KINDS`、`R3_MARGIN` 不进入实现。
   - “只用仿射”的结果另算，写入 `registration.json` 的比较字段，只供 TASK-153 的盲测报告使用（§10.3），不进入 `regions.json`，也不作选择依据。
   - 失败时状态记 `failed`，以上一次已确认的多边形为起点；还没有已确认的录制时用原多边形。
6. **检查项与顶点提示**（§7）：七项检查与顶点提示按 §7 计算，数值写入 `registration.json`。全部正常记 `proposed`，有一项不正常记 `attention` 并写明是哪一项。检查项只作提示，不决定区域是否可用。
7. **工作区**（§8）：每个顶点用周围 260 像素内的锚点局部拟合，点数不足时退回粗对齐并注明。状态固定为 `attention`。
8. **可移动物体**（§9）：本任务不配准 `item_box`。输出起点（上一次确认的多边形，没有时用原多边形）、6 个时段的背景缩略图，并标出与前一时段差别较大的时段。标出的规则写入 `monitor.json`，只作提示。
9. **录制内监测**（§10.1）：
   - 6 个时段，每时段 20 帧建背景，比较各时段与第一时段，参数按 §10.1。
   - 事件：固定区域的顶点位移中位数 ≥ 1.0 像素。在事件附近加密取样定位，前后分成两段各自配准。过渡时段写 `uncertain: true`，范围按 §10.1。
   - 外观变化只用来提示推车，不用来判断位移。
10. **参考**（§10.4）：默认参考是用户在 `20260821` 上画的区域。没有得到模型或提示较多时，用最近一次已确认的录制重试，`--reference-session` 可以指定，结果记录实际参考。不串联配准。
11. **输出**（§12）：
    - 文件与字段按 §12，放在 `gazelle_data\workdata\roi_sessions\`。
    - `status` 只能是 `proposed`、`attention`、`failed`。`source` 按实际：配准得到的记 `registered`，`item_box` 与 `failed` 的起点记起点多边形的来源。`item_box` 的 `status` 固定为 `attention`。这几条设计没有写，由协调者定。
    - `20260821` 也由本任务写出：多边形就是原区域，`source` 记 `drawn`，`status` 记 `proposed`，用户确认由 TASK-153 改写。
    - `start_s`、`end_s` 用以 B 为基准的同步时间轴；`monitor.json` 另记 E 的文件时间。
    - 坐标归一化并裁到画面内，未裁剪的结果在 `registration.json`。
    - 原子写入。已有结果不覆盖，除非显式传 `--force`；已有 `reviewed` 的区域时，`--force` 也拒绝。
12. **文档与测试**：
    - `tools/workdata/README_CN.md` 写明命令、输入与输出。这是内部工具，四份用户文档只在说明数据流程的地方加一行；是否需要由实现者判断，写入报告。
    - 默认测试用合成图像，不读真实录像，覆盖下面验收的离线部分。

### 非目标

- 不逐帧跟踪，不把多边形吸附到边缘，不修正多边形本身画得不准的地方。
- 不自动识别推车，不用自动检查代替人工确认。
- 只处理 E。A、B、W 没有区域。摄像机运动的问题交给 TASK-305。
- 不写 `reviewed`，不做复核页面与盲测，这些在 TASK-153。
- 不改正式区域、完成标记、参考图与类别文件。不生成阶段 3 的产物。

### 不可变约束

- 正式区域文件只读，`roi_regions.json` 的 SHA-256 前后相同。
- 源目录只读。派生数据只写到 `gazelle_data\workdata\roi_sessions\` 与 `gazelle_runs\task-151\`。背景图与缩略图只在本机，不提交，不上传。
- 不修改环境，不安装依赖。OpenCV 的 SIFT 与 `USAC_MAGSAC` 在 `Gazelle-next` 中可用，2026-10-31 已核对。
- 不改 `sync_*`、`proxies`、`timemap` 的受保护组件。

### 允许动作

读全库；写 `tools/workdata/`、`tests/`、上面列出的说明文档；在阶段分支提交并推送；运行下面的真实检查。

### 验收标准

离线：

1. 已知位移、旋转与透视能恢复。
2. 图像不同部分各自移动时，每个区域得到自己的结果。
3. 光照、噪声、压缩、遮挡与移动的物品下仍然得到结果。
4. 负样本：无关画面得不到模型；外来模型被提示。
5. 注入小位移时，监测报事件，并分成两段。
6. 输出格式与原子写入；`--force` 不覆盖 `reviewed`；原区域文件不被改动。

真实运行（只读，只用 CPU）。这些主要证明实现与原型一致，因为参数就是在这批录制上定的：

| 项目 | 通过标准 |
| --- | --- |
| 与原型一致 | 全部录制的顶点差中位数 ≤ 1 像素，参照 `v3_table.json` |
| 前后两半 | 最差 ≤ 3 像素 |
| 闭环 | 每个区域的最大差 P90 ≤ 6 像素 |
| 负样本 | 镜像与上下颠倒没有模型或被提示；外来模型（错层模拟）全部被提示 |
| 注入的位移 | 真实分时段背景上整幅注入 2 像素，全部被发现 |
| 正式文件 | `roi_regions.json` 的 SHA-256 不变 |

- 录制范围：全部 10 次录制。`20261030` 在 TASK-152 生成代理之后运行；TASK-152 与本任务同在第 10 轮，先做 TASK-152。
- 实测与标准不符时按 B 级报告，不调参数去迎合。
- 复核页面要用的字段由 TASK-153 读取，字段变化要写入报告。
